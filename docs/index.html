Why KWin should tell the kernel what changed

Panel self refresh, selective update, and the FB_DAMAGE_CLIPS property: how a laptop's built-in screen saves power when most of it isn't changing, and why KWin currently stops it from saving as much as it could.

The screen is mostly still

A laptop's internal panel is connected over eDP (embedded DisplayPort). In the simplest setup the GPU's display engine reads the whole frame from memory and sends it down the link 60 or 120 times a second, even if nothing on screen has moved. That costs power in three places: memory reads, the display engine itself, and the link.

Most of the time very little changes. A blinking cursor, a clock, a scrolling chat. The rest of the screen is the same picture as the frame before.

Panel self refresh

Panels that support PSR (Panel Self Refresh) have a small frame buffer of their own. When the image stops changing, the GPU sends one last frame, the panel keeps refreshing itself from its own copy, and the GPU can stop sending. The link powers down, memory goes quiet, and the display engine can drop into its deeper power states.

The catch with the first version, PSR1, is that any change at all ends it. One cursor blink and the GPU has to wake up and send the whole frame again.

Selective update: send only the part that changed

PSR2 and its successor Panel Replay add selective update. The panel stays in self refresh, and the GPU sends only the region that changed. On Intel GPUs the matching feature on the source side is selective fetch: the display engine reads only those lines from memory, not the whole frame.

To do that, the kernel has to know which part of the screen changed. It can't work that out itself: comparing frames would cost more than it saves. The compositor already knows, because it just drew the frame.

Damage clips: how the compositor says what changed

On Linux a compositor such as KWin hands each frame to the kernel through an atomic commit, one per refresh, listing the buffers for each plane (the main picture, the cursor, any overlays). Each plane has an optional property, FB_DAMAGE_CLIPS, which is a list of rectangles: the parts of the buffer that changed since the last commit. "Damage" is the usual graphics word for "needs redrawing".

The rule in the kernel's damage helper (drm_atomic_helper_damage_iter_init()) is simple: a plane that is in the commit with no damage clips is treated as fully damaged. That's the safe default, because the kernel can't assume anything stayed the same.

What KWin does today

KWin sets FB_DAMAGE_CLIPS to 0, meaning "no clips", on every plane in every commit. That's deliberate: a previous program holding the display could have left a stale damage list behind, and the kernel doesn't reset it, so clearing it is the safe thing to do. But it means that every commit that includes the main plane is full height, however little changed.

So on a PSR2 or Panel Replay panel, KWin gets selective update in name only. The panel still self-refreshes on a completely static screen, but as soon as anything moves, such as a blinking cursor, a ticking clock, or a progress bar, the whole frame is fetched from memory and sent down the link again.

The upstream change that would fix this is KWin merge request !3548, "backends/drm: add support for FB_DAMAGE_CLIPS", which names PSR2 power as its motivation. It's open and targeted at Plasma 6.9.

What the patch does

The patch in this repo is a smaller port of the same idea, written against the KWin that Fedora ships:

  • After KWin composites a frame, it records the region it actually redrew and sends it as FB_DAMAGE_CLIPS on the next commit.
  • Damage from a frame that was drawn but never sent is kept and added to the next one, and when KWin merges two pending commits it merges their damage too. Otherwise the panel could miss an update.
  • Anywhere it can't be sure, it keeps the old behaviour and sends 0: direct scanout (a fullscreen game or video handed straight to the display), the first frame after it, cursor and software layers, and scaled, rotated or offset planes.

It touches seven files under src/backends/drm/, about 130 added lines.

What it changes in practice

Measured on an Intel Panther Lake–family laptop (Xe3 display, 2560×1600 eDP panel running Panel Replay with selective update) with this patch on Fedora's KWin 6.8. "Partial" is the share of commits the kernel sent as a selective update instead of a full frame; "area" is the average share of the screen each update covered.

What was on screenPartialArea
Idle desktop100%10%
Static window, mouse moving99%4%
Small video window100%24%
Half-screen video window100%62%
Fullscreen video (direct scanout)0%100%

With stock KWin, the same machine sent about 95 to 100% of updates at full height. The fullscreen row is full height with or without the patch, because direct scanout bypasses compositing and the patch sends no clips there. No kernel errors or uncovered damage were seen in any run.

The battery saving itself hasn't been measured against stock KWin on the same setup yet, so this page doesn't put a number on it. What's measured is that the display hardware now fetches and sends a fraction of the screen instead of all of it. That's the work PSR2 and Panel Replay exist to avoid.

Who this helps

Laptops whose built-in panel supports PSR2 or Panel Replay with selective update, on a driver that reads FB_DAMAGE_CLIPS. The patch has only been tested on Intel's xe driver. On anything else it should change nothing: drivers that ignore the property keep doing full updates, as they do today.

Installing it on Fedora

The repository rebuilds Fedora's own kwin with this one patch, in COPR, whenever Fedora's stable kwin changes.

sudo dnf copr enable karanshukla/kwin-damage-copr
sudo dnf upgrade kwin kwin-common kwin-libs

Then log out and back in. To check whether your hardware is using selective update, look at /sys/kernel/debug/dri/0/i915_edp_psr_status as root. It should say PSR2 or Panel Replay Selective Update, with selective fetch enabled. To go back to stock: sudo dnf copr remove karanshukla/kwin-damage-copr && sudo dnf distro-sync kwin kwin-common kwin-libs.

This is a stopgap until KWin ships damage clips itself. The patch and build scripts are GPL-2.0-or-later, like KWin. Source, build process and security notes: github.com/karanshukla/kwin-damage-copr.
